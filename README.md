# Лабораторная работа: поиск в пространстве состояний. Задача «Волк, коза и капуста»

**Дисциплина:** Интеллектуальные системы
**Тема:** Неинформированный (слепой) поиск в пространстве состояний
**Алгоритмы:** поиск в ширину (BFS), поиск в глубину (DFS), поиск с итеративным углублением (IDS)
**Язык / среда:** C++17, Microsoft Visual Studio (проект `WolfGoatCabbage.sln`)

---

## 1. Цель работы

Изучить представление задач в пространстве состояний и методы неинформированного
поиска на графе состояний. Реализовать алгоритмы BFS, DFS и IDS для классической задачи
«Волк, коза и капуста», получить решение, выполнить трассировку работы алгоритмов и
сравнить их по полноте, оптимальности, затратам времени и памяти.

## 2. Постановка задачи

Крестьянину нужно переправить через реку волка, козу и капусту. Лодка вмещает
крестьянина и не более одного груза; без крестьянина лодка не плывёт. Если оставить
без присмотра волка с козой, волк съест козу; если оставить козу с капустой, коза
съест капусту. Требуется найти последовательность переправ, после которой все четверо
окажутся на противоположном берегу, а ограничения ни разу не будут нарушены.

## 3. Формализация задачи

### 3.1. Состояние

Состояние описывается вектором `s = (f, w, g, c)`, где каждая компонента — номер
берега, на котором находится объект: `0` — левый (исходный) берег, `1` — правый
(целевой).

| Компонента | Объект | Обозначение в программе |
|---|---|---|
| `f` | крестьянин (и лодка — она всегда у крестьянина) | `F` |
| `w` | волк | `W` |
| `g` | коза | `G` |
| `c` | капуста | `C` |

В программе состояние упаковано в 4 младших бита байта (`State = uint8_t`), а для
вывода используется код `fwgc` (например, `1010`) и «картинка» берегов:
`.W.C |~~~~| F.G.` — слева от реки волк и капуста, справа крестьянин и коза.

- **Начальное состояние:** `s0 = (0,0,0,0)` — `FWGC |~~~~| ....`
- **Целевое состояние:** `sg = (1,1,1,1)` — `.... |~~~~| FWGC`

### 3.2. Ограничения (допустимость состояния)

Состояние допустимо, если не выполняется ни одно из условий:

- `w = g` и `f ≠ g` — волк с козой без крестьянина;
- `g = c` и `f ≠ g` — коза с капустой без крестьянина.

### 3.3. Операторы

Четыре оператора — варианты загрузки лодки:

| Оператор | Смысл | Условие применимости | Результат |
|---|---|---|---|
| `F` | крестьянин плывёт один | всегда | `f := 1 − f` |
| `F+W` | везёт волка | `w = f` | `f := 1 − f`, `w := 1 − w` |
| `F+G` | везёт козу | `g = f` | `f := 1 − f`, `g := 1 − g` |
| `F+C` | везёт капусту | `c = f` | `f := 1 − f`, `c := 1 − c` |

Оператор порождает допустимый переход, если его результат — допустимое состояние.
Все операторы обратимы, поэтому граф состояний неориентированный. Стоимость каждой
переправы равна 1, т. е. оптимальное решение — решение с минимальным числом переправ.

### 3.4. Пространство состояний

Всего `2⁴ = 16` состояний, из них **допустимы 10** (вывод программы, пункт меню 5):

| Код `fwgc` | Картинка | Допустимо |
|---|---|---|
| 0000 | `FWGC \|~~~~\| ....` | да (начальное) |
| 1000 | `.WGC \|~~~~\| F...` | нет — волк съест козу, коза съест капусту |
| 0100 | `F.GC \|~~~~\| .W..` | да |
| 1100 | `..GC \|~~~~\| FW..` | нет — коза съест капусту |
| 0010 | `FW.C \|~~~~\| ..G.` | да |
| 1010 | `.W.C \|~~~~\| F.G.` | да |
| 0110 | `F..C \|~~~~\| .WG.` | нет — волк съест козу |
| 1110 | `...C \|~~~~\| FWG.` | да |
| 0001 | `FWG. \|~~~~\| ...C` | да |
| 1001 | `.WG. \|~~~~\| F..C` | нет — волк съест козу |
| 0101 | `F.G. \|~~~~\| .W.C` | да |
| 1101 | `..G. \|~~~~\| FW.C` | да |
| 0011 | `FW.. \|~~~~\| ..GC` | нет — коза съест капусту |
| 1011 | `.W.. \|~~~~\| F.GC` | да |
| 0111 | `F... \|~~~~\| .WGC` | нет — волк съест козу, коза съест капусту |
| 1111 | `.... \|~~~~\| FWGC` | да (целевое) |

Граф допустимых состояний (10 вершин, 10 рёбер; на рёбрах — операторы):

```
                              F+W           F+G           F+C
                        ┌──────────── 1110 ──────── 0100 ────────┐
                        │                                        │
 0000 ──F+G── 1010 ──F── 0010                                    1101 ──F── 0101 ──F+G── 1111
                        │                                        │
                        └──────────── 1011 ──────── 0001 ────────┘
                              F+C           F+G           F+W
```

Граф состоит из «хвоста» `0000 – 1010 – 0010`, цикла из 6 состояний и «хвоста»
`1101 – 0101 – 1111`. Отсюда сразу видно, что задача имеет **ровно два** простых
решения, оба длиной **7 переправ** — они отличаются тем, кого крестьянин везёт
второй ходом: волка (верхняя ветвь) или капусту (нижняя ветвь). Программа подтверждает
это полным перебором простых путей (пункт меню 6).

Характеристики пространства для оценки сложности:

- максимальный коэффициент ветвления `b = 4` (число операторов), фактический
  (после отбрасывания недопустимых и обратных ходов) — около 1–2;
- глубина ближайшего решения `d = 7`;
- максимальная глубина дерева при поиске с контролем повторов `m ≤ |S| − 1 = 9`;
  фактически самый длинный простой путь в этом графе — 7 рёбер.

## 4. Алгоритмы поиска

Во всех алгоритмах используется дерево поиска: узел хранит состояние, ссылку на
родителя, оператор, которым он получен, и глубину. Решение восстанавливается
проходом от целевого узла к корню по ссылкам на родителя. Множество узлов,
ожидающих раскрытия, называется **OPEN** (фронт), множество уже раскрытых
состояний — **CLOSED**. Операторы перебираются в фиксированном порядке
`F, F+W, F+G, F+C`.

### 4.1. Поиск в ширину (BFS)

OPEN — очередь FIFO. Узлы раскрываются в порядке возрастания глубины, поэтому
первое найденное решение — кратчайшее (при единичной стоимости шагов).

```
BFS(s0, goal):
    если s0 = goal: вернуть решение
    OPEN := очередь{узел(s0)};  REACHED := {s0}
    пока OPEN не пуста:
        n := OPEN.извлечь_первый()
        для каждого допустимого перехода n.s --op--> s':
            если s' ∈ REACHED: пропустить
            child := узел(s', родитель n, op);  REACHED := REACHED ∪ {s'}
            если s' = goal: вернуть путь(child)        // проверка при порождении
            OPEN.добавить_в_конец(child)
    вернуть «решения нет»
```

Проверка на цель выполняется при **порождении** узла (а не при раскрытии) — это
экономит целый уровень дерева. Повторные состояния отсекаются множеством REACHED
(поиск на графе), поэтому каждое состояние попадает в очередь не более одного раза.

### 4.2. Поиск в глубину (DFS)

OPEN — стек LIFO, раскрывается самый глубокий узел. Реализован итеративно на явном
стеке (это позволяет показать содержимое стека в трассировке). Потомки кладутся в
стек в обратном порядке, чтобы первым раскрывался первый по порядку оператор.

```
DFS(s0, goal):
    OPEN := стек{узел(s0)};  CLOSED := ∅
    пока OPEN не пуст:
        n := OPEN.извлечь_вершину()
        если n.s ∈ CLOSED: пропустить
        если n.s = goal: вернуть путь(n)               // проверка при извлечении
        CLOSED := CLOSED ∪ {n.s}
        для каждого допустимого перехода n.s --op--> s' (в обратном порядке):
            если s' ∉ CLOSED: OPEN.положить(узел(s', родитель n, op))
    вернуть «решения нет»
```

Используется список CLOSED (поиск на графе): раскрытое состояние повторно не
раскрывается. Без него поиск не завершился бы: все операторы обратимы, а первым
применимым оператором в состоянии `1010` является «крестьянин плывёт один», поэтому
лодка бесконечно ходила бы между `1010` и `0010`. С CLOSED алгоритм полон на
конечном графе, но не гарантирует оптимальность.

### 4.3. Поиск с итеративным углублением (IDS)

Последовательность поисков в глубину с ограничением глубины `L = 0, 1, 2, …`
(Depth-Limited Search, DLS). Сочетает оптимальность BFS и линейную память DFS.

```
IDS(s0, goal):
    для L = 0, 1, 2, …, maxDepth:
        результат := DLS(s0, goal, L)
        если результат = НАЙДЕНО: вернуть путь
        если результат = НЕУДАЧА: вернуть «решения нет»    // отсечений не было

DLS(s, goal, L, глубина):
    если s = goal: вернуть НАЙДЕНО
    если глубина = L: вернуть ОТСЕЧЕНИЕ
    было_отсечение := ложь
    для каждого допустимого перехода s --op--> s', где s' не лежит на текущем пути:
        r := DLS(s', goal, L, глубина + 1)
        если r = НАЙДЕНО: вернуть НАЙДЕНО
        если r = ОТСЕЧЕНИЕ: было_отсечение := истина
    вернуть было_отсечение ? ОТСЕЧЕНИЕ : НЕУДАЧА
```

Список CLOSED не ведётся (иначе теряется главное преимущество — линейная память);
отсекаются только циклы — состояния, уже лежащие на текущем пути. Различение
результатов ОТСЕЧЕНИЕ / НЕУДАЧА позволяет корректно завершить поиск, если решения
не существует, а не перебирать глубины до `maxDepth`.

### 4.4. Теоретические свойства

| Свойство | BFS | DFS | IDS |
|---|---|---|---|
| Полнота | да (при конечном `b`) | да — на конечном графе со списком CLOSED; без него возможно зацикливание | да |
| Оптимальность (при единичной стоимости) | да | **нет** | да |
| Время | `O(b^d)` | `O(b^m)` | `O(b^d)` |
| Память | `O(b^d)` | `O(b·m)` — дерево; `O(|S|)` — с CLOSED | `O(b·d)` |

Здесь `b` — коэффициент ветвления, `d` — глубина ближайшего решения, `m` —
максимальная глубина дерева поиска, `|S|` — число состояний.

### 5.2. Основные структуры и функции

| Элемент | Назначение |
|---|---|
| `State` (`uint8_t`) | состояние, бит `i` — берег объекта `i` (0 — F, 1 — W, 2 — G, 3 — C) |
| `IsValid(s)` | проверка ограничений задачи |
| `AllTransitions(s)` | все применимые операторы с результатом и признаком допустимости (нужно для трассировки — показать, почему ход отброшен) |
| `Successors(s)` | только допустимые переходы |

| `SolveBFS`, `SolveDFS`, `SolveIDS` | алгоритмы поиска с необязательной трассировкой в поток |
| `EnumerateAllSolutions` | перебор всех простых путей (для анализа пространства) |

Применение оператора сводится к инверсии битов: крестьянина — всегда, груза — если он
есть (`Apply(s, c) = s ^ 1 ^ (1 << c)`). Поскольку состояний всего 16, множества
REACHED / CLOSED / «на пути» реализованы массивами `std::array<bool, 16>` с доступом
за `O(1)`.

### 5.3. Собираемая статистика

| Показатель | Смысл |
|---|---|
| Раскрыто | число узлов, для которых построены потомки |
| Порождено | число узлов, добавленных в дерево поиска (включая корень; у IDS — суммарно по всем итерациям) |
| Отброшено недопустимых | ходы в состояния, нарушающие ограничения |
| Отброшено повторных | ходы в уже встречавшиеся состояния (у IDS — в состояния текущего пути) |
| max OPEN | максимальный размер фронта: очереди BFS / стека DFS / текущего пути IDS — оценка затрат памяти |
| CLOSED | число запомненных посещённых состояний |
| Время | среднее время одного запуска без трассировки; задача решается за микросекунды, поэтому поиск повторяется в течение ~0,2 с и время усредняется |

Исходники в UTF-8, в проекте включён ключ компилятора `/utf-8`; консоль переводится в

```
  1 - BFS (поиск в ширину)
  2 - DFS (поиск в глубину, со списком CLOSED)
  3 - IDS (поиск с итеративным углублением)
  4 - Сравнить все алгоритмы
  5 - Показать пространство состояний
  6 - Найти все решения (простые пути)
  7 - Задать начальное / целевое состояние
```

с указанием причины.

Запуск с ключом `--report` выполняет все эксперименты без участия пользователя;

## 7. Результаты

### 7.1. Найденное решение

BFS, DFS и IDS из начального состояния находят одно и то же решение из 7 переправ:

```
   0. [0000] FWGC |~~~~| ....   (начальное состояние)
   1. [1010] .W.C |~~~~| F.G.   Крестьянин перевозит козу слева направо
   2. [0010] FW.C |~~~~| ..G.   Крестьянин плывёт один справа налево
   3. [1110] ...C |~~~~| FWG.   Крестьянин перевозит волка слева направо
   4. [0100] F.GC |~~~~| .W..   Крестьянин перевозит козу справа налево
   5. [1101] ..G. |~~~~| FW.C   Крестьянин перевозит капусту слева направо
   6. [0101] F.G. |~~~~| .W.C   Крестьянин плывёт один справа налево
   7. [1111] .... |~~~~| FWGC   Крестьянин перевозит козу слева направо
```

Второе оптимальное решение (найдено перебором всех простых путей) отличается шагами
3–5: сначала перевозится капуста, затем коза возвращается, затем перевозится волк.

### 7.2. Фрагмент трассировки BFS

```
Шаг 1. Из очереди извлечён узел #0 [0000] FWGC |~~~~| ...., глубина 0
    F   -> [1000] .WGC |~~~~| F...  отброшен: волк съест козу, коза съест капусту
    F+W -> [1100] ..GC |~~~~| FW..  отброшен: коза съест капусту
    F+G -> [1010] .W.C |~~~~| F.G.  новый узел #1
    F+C -> [1001] .WG. |~~~~| F..C  отброшен: волк съест козу
  OPEN (очередь):   [1010]
  Встречено:        {0000, 1010}
Шаг 2. Из очереди извлечён узел #1 [1010] .W.C |~~~~| F.G., глубина 1
    F   -> [0010] FW.C |~~~~| ..G.  новый узел #2
    F+G -> [0000] FWGC |~~~~| ....  отброшен: уже встречалось
  OPEN (очередь):   [0010]
  ...
Шаг 9. Из очереди извлечён узел #8 [0101] F.G. |~~~~| .W.C, глубина 6
    F   -> [1101] ..G. |~~~~| FW.C  отброшен: уже встречалось
    F+G -> [1111] .... |~~~~| FWGC  новый узел #9
  Узел #9 - целевой. Поиск завершён.
```

Из начального состояния допустим единственный ход — перевезти козу: любой другой
оставляет козу без присмотра с волком или с капустой. Полные трассировки всех
алгоритмов приведены в [results.txt](results.txt).

### 7.4. Сравнение алгоритмов

**Эксперимент 1.** Исходная задача `0000 → 1111`:

| Алгоритм | Длина решения | Раскрыто | Порождено | max OPEN | CLOSED | Время, мкс |
|---|---|---|---|---|---|---|
| BFS | 7 | 9 | 10 | 2 | 10 | ≈2,0 |
| DFS | 7 | 7 | 10 | 3 | 7 | ≈2,0 |
| IDS | 7 | 34 | 48 | 8 | 0 | ≈7,1 |

**Эксперимент 2.** Старт на цикле графа: `1110 → 1111`
(`...C |~~~~| FWG.` — слева осталась только капуста). Кратчайшее решение — 4 переправы.

| Алгоритм | Длина решения | Раскрыто | Порождено | max OPEN | CLOSED | Время, мкс |
|---|---|---|---|---|---|---|
| BFS | 4 | 9 | 10 | 3 | 10 | ≈1,9 |
| DFS | **6** | 8 | 11 | 3 | 8 | ≈2,1 |
| IDS | 4 | 19 | 31 | 5 | 0 | ≈3,8 |

Решение DFS в этом эксперименте:

```
   0. [1110] ...C |~~~~| FWG.   (начальное состояние)
   1. [0010] FW.C |~~~~| ..G.   Крестьянин перевозит волка справа налево
   2. [1011] .W.. |~~~~| F.GC   Крестьянин перевозит капусту слева направо
   3. [0001] FWG. |~~~~| ...C   Крестьянин перевозит козу справа налево
   4. [1101] ..G. |~~~~| FW.C   Крестьянин перевозит волка слева направо
   5. [0101] F.G. |~~~~| .W.C   Крестьянин плывёт один справа налево
   6. [1111] .... |~~~~| FWGC   Крестьянин перевозит козу слева направо
```

Оптимальный путь — `1110 → 0100 → 1101 → 0101 → 1111` (вернуть козу, перевезти
капусту, вернуться, перевезти козу).

**Эксперимент 3.** Цель в одной переправе: `0101 → 1111`:

| Алгоритм | Длина решения | Раскрыто | Порождено | max OPEN | CLOSED | Время, мкс |
|---|---|---|---|---|---|---|
| BFS | 1 | 1 | 3 | 1 | 3 | ≈0,5 |
| DFS | 1 | 9 | 11 | 4 | 9 | ≈2,0 |
| IDS | 1 | 1 | 4 | 2 | 0 | ≈0,4 |

Время измерено на конфигурации Release x64 и зависит от компьютера; значимо только
соотношение между алгоритмами.

## 8. Анализ результатов

1. **Оптимальность.** BFS и IDS во всех экспериментах нашли кратчайшее решение, что
   соответствует теории: оба алгоритма перебирают узлы в порядке неубывания глубины.
   DFS в эксперименте 1 тоже дал решение длины 7, но лишь потому, что в этой задаче
   из начального состояния оба простых пути имеют одинаковую длину. В эксперименте 2
   DFS первым применил оператор `F+W` и ушёл по циклу графа «длинной» дорогой,
   вернув решение из 6 переправ вместо 4 — **DFS не гарантирует оптимальность**.

2. **Контроль повторных состояний.** Граф состояний содержит циклы (все операторы
   обратимы), поэтому без списка CLOSED поиск в глубину не завершился бы: в
   состоянии `1010` первым применимым оператором является `F`, и лодка бесконечно
   ходила бы между `1010` и `0010`. Список CLOSED делает DFS полным на конечном
   графе; цена — память `O(|S|)` (в эксперименте 1 в CLOSED оказалось 7 состояний).

3. **Затраты памяти.** BFS хранит всю «границу» и все встреченные состояния
   (CLOSED = 10 — всё пространство); IDS хранит только текущий путь (max OPEN ≤ d + 1)
   и не хранит CLOSED вовсе. Для данной задачи разница несущественна (всего 10
   состояний), но для задач с экспоненциальным пространством именно память является
   узким местом BFS (`O(b^d)` против `O(b·d)` у IDS).

4. **Повторная работа IDS.** IDS раскрыл 34 узла против 9 у BFS, т. е. в ~4 раза
   больше. Теоретически избыточность IDS относительно BFS составляет примерно
   `b / (b − 1)`, что при `b = 10` даёт лишь ~11 %. Однако здесь эффективный
   коэффициент ветвления близок к 1 (граф почти линеен: у большинства состояний один
   «новый» сосед), поэтому верхние уровни дерева, повторно обходимые на каждой
   итерации, составляют большую часть работы. Это хорошо видно по таблице итераций:
   число раскрытых узлов растёт с `L` почти линейно (0, 1, 2, 3, 5, 7, 9, 7), а не
   экспоненциально, поэтому суммарная работа IDS порядка `d²/2`, а не `d`.
   Если же цель близка (эксперимент 3), IDS почти не проигрывает BFS.

5. **Время.** Пространство состояний очень мало, поэтому все алгоритмы работают
   за единицы микросекунд; соотношение времён соответствует соотношению числа
   порождённых узлов.

6. **Структура задачи.** Анализ графа показывает, почему задача кажется человеку
   «хитрой»: из начального состояния возможен единственный ход (перевезти козу), а
   ключевой шаг решения — вернуть козу обратно (шаг 4) — кажется движением «назад»,
   хотя в графе состояний это просто ребро на единственной дороге к цели.

## 9. Выводы

В работе задача «Волк, коза и капуста» формализована как задача поиска в
пространстве состояний: состояние — четвёрка номеров берегов, 4 оператора, 10
допустимых состояний из 16. Реализованы алгоритмы BFS, DFS (со списком CLOSED) и IDS
с трассировкой и сбором статистики.

Все реализованные алгоритмы нашли решение исходной задачи из 7 переправ, которое
является оптимальным; перебором простых путей установлено, что оптимальных решений
ровно два. Эксперименты подтвердили теоретические свойства алгоритмов:

- **BFS** полон и оптимален, но хранит в памяти все встреченные состояния;
- **DFS** экономен по памяти и может найти решение быстро, но не гарантирует его
  оптимальность (6 переправ вместо 4 в эксперименте 2), а для полноты на графе с
  циклами требует списка CLOSED;
- **IDS** сочетает оптимальность BFS с линейной памятью DFS ценой повторного обхода
  верхних уровней дерева; эта плата велика при малом коэффициенте ветвления (как в
  данной задаче) и мала при большом.

Для задач малой размерности, как рассмотренная, оптимален BFS; для задач с большим
пространством состояний и неизвестной глубиной решения среди неинформированных
методов предпочтителен IDS.

## 10. Контрольные вопросы

1. **Что такое пространство состояний?** Четвёрка ⟨S, s0, O, G⟩: множество
   состояний, начальное состояние, множество операторов перехода и целевое условие.
   Решение — последовательность операторов, переводящая s0 в целевое состояние.

2. **Чем отличается поиск на дереве от поиска на графе?** Поиск на графе запоминает
   посещённые состояния (CLOSED) и не раскрывает их повторно; поиск на дереве этого не
   делает и при наличии циклов может зациклиться или многократно повторять работу.

3. **Почему BFS находит кратчайшее решение?** Узлы раскрываются в порядке
   неубывания глубины, поэтому решение глубины `d` не может быть найдено раньше, чем
   будут исчерпаны все узлы глубины `d − 1`.

4. **Почему IDS не намного медленнее BFS?** Число узлов в дереве растёт
   экспоненциально с глубиной, поэтому большая часть узлов находится на последнем
   уровне, а повторный обход верхних уровней даёт множитель около `b/(b − 1)`.

5. **Когда проверять узел на цель — при порождении или при раскрытии?** Для BFS
   допустима проверка при порождении (экономит один уровень, оптимальность при
   единичной стоимости сохраняется). Для алгоритмов, учитывающих стоимость пути
   (поиск по критерию стоимости, A*), проверка должна выполняться при раскрытии,
   иначе возможно неоптимальное решение.
